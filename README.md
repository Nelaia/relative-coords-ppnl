# Absolute vs. relative coordinates for fine-tuned SLM grid navigation (PPNL)

Code, adapters and per-sample predictions for the paper *Relative Coordinate Representations for Grid Path Planning with a Small Language Model: Reference Frames and Input Formats on PPNL (under review).
Base model: `Qwen/Qwen2.5-3B` (QLoRA). Base benchmark: PPNL, Aghzal et al. (https://github.com/MohamedAghzal/llms-as-path-planners).

## Conditions

| Code | Input | HF adapter folder |
|---|---|---|
| A | absolute coordinates (original PPNL) | `a_abs_single-goal-original` |
| R-num | `(dx,dy)` relative to the robot | `rnum_rel-robot_single-goal-original` |
| R-nl | natural language, relative to the robot | `rnl_rel-robot_single-goal-original` |
| G-num | `(dx,dy)` relative to the goal | `gnum_rel-goal_single-goal-original` |
| G-nl | natural language, relative to the goal | `gnl_rel-goal_single-goal-original` |

Adapters: https://huggingface.co/Nelaia/qwen2.5-3b-ppnl-lora (load with `PeftModel.from_pretrained(base, repo, subfolder=<folder>)`).

## Data

The original PPNL data (`single_goal_original/` with `iid/` and `ood/`) is **not** redistributed here; download it from the PPNL repository
and point `--ppnl_root` / `PPNL_ROOT` at it. The four relative variants are generated by `src/make_condition.py`; every converted example is
mapped back to absolute coordinates and checked against the `world` grid (zero mismatches over all splits). All OOD splits come from PPNL.
Examples marked "Goal not reachable" are excluded from every evaluation (`data.is_reachable`).

## Pipeline

```bash
pip install -r requirements.txt
export PPNL_ROOT=/path/to/single_goal_original

# 1. build a relative-condition dataset (skip for A)
python src/make_condition.py --cond rnl --src $PPNL_ROOT --dst data_rnl

# 2. train (seed 1, 3 epochs, lr 2e-4, LoRA r16/a32/0.05, NF4, paged AdamW 8-bit, cosine, warmup 0.03; effective batch 32)
PPNL_ROOT=$PPNL_ROOT                python src/train.py --run_name a_abs_single-goal-original              --max_seq_len 128 --bs 32
PPNL_ROOT=data_rnum                 python src/train.py --run_name rnum_rel-robot_single-goal-original     --max_seq_len 256 --bs 32
PPNL_ROOT=data_gnum                 python src/train.py --run_name gnum_rel-goal_single-goal-original      --max_seq_len 256 --bs 32
PPNL_ROOT=data_rnl                  python src/train.py --run_name rnl_rel-robot_single-goal-original      --max_seq_len 365 --bs 16 --grad_accum 2
PPNL_ROOT=data_gnl                  python src/train.py --run_name gnl_rel-goal_single-goal-original       --max_seq_len 365 --bs 16 --grad_accum 2

# 3. evaluate with the PPNL-derived metrics (Tables 3, 5, 6), then upload
PPNL_ROOT=data_rnl python src/eval.py --run_name rnl_rel-robot_single-goal-original
python src/push_hf.py --run_name rnl_rel-robot_single-goal-original
python src/collect_results.py                 # -> comparison/all_results.csv, hyperparams.csv

# 4. per-sample predictions (30 CSVs -> outputs/all_predictions.zip)
python src/generate_predictions.py --ppnl_root $PPNL_ROOT

# 5. analyses
python src/evaluate_results.py                # failure modes, index-6, border analysis (run from the folder holding all_predictions.zip)
python src/stats.py --zip outputs/all_predictions.zip      # Table 4: McNemar exact + Wald 95% CI + Holm
python src/make_figures.py --results comparison/all_results.csv --zip outputs/all_predictions.zip
```

## Notes

- `eval.py` keeps the metric logic of PPNL's `executor-point-sg.py` (source of Tables 3, 5, 6). `evaluate_results.py` re-simulates plans from the
  prediction CSVs and is used for McNemar tests, the index-6 and border analyses; the two agree to within 0.06 points on Success rate.
- Prediction CSV columns: `id` (position after filtering unreachable examples), `orig_idx` (index in the original PPNL json), `input`, `answer`, `pred`.
- Checkpoints were selected by Exact match on the first 500 reachable dev examples.
- Hardware: Kaggle 2xT4. Greedy decoding, `max_new_tokens=48`.
- Licenses: code is MIT (see LICENSE). Check the PPNL repository license for the data and the Qwen2.5-3B model card for the base-model terms
  that apply to the adapters.
